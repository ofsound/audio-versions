Audio Versions: highest-value features

These are ranked by how much each improves the main job of the web, desktop, and iPhone apps, which is comparing mixes of a song and tracking feedback on them. Each one is weighed against what the code already does.

Top five

  1. 1

    Instant A/B switching between versions at the same position

    Right now each version keeps its own playhead (playheadMsByFileId), so comparing “the same chorus in v3 and v4” means seeking by hand on each card. Add a shared play position for the song, so pressing 1–9 or clicking another version switches at the same timestamp without a gap. Add an optional per-version time offset for bounces that start at different points.

    Of the five, this matters most for an app built around versions.

    Web + ElectronSong workspace playback
  2. 2

    Loudness-matched comparison

    You already measure integrated LUFS (overall loudness) for every file, but the app only displays it. Playback gain is still the manual volumeDb stepper. A “Match loudness” toggle could set each version’s gain from its LUFS reading so they play at equal loudness.

    Louder mixes tend to sound better, which skews comparisons, so this makes A/B judgments more honest. The data is already there, so it’s cheap to build, and it pairs naturally with the first feature.

    Web + ElectronLow effort
  3. 3

    Loop a range

    Range annotations exist, but only playlists can loop. Looping the selected range (with a shortcut like L) is basic to mix review, especially combined with A/B switching: you could loop the bridge and flip between versions.

    It’s small to build because the range data and drag handling already exist.

    Web + ElectronLow effort
  4. 4

    Mark feedback as resolved and carry it to the next version

    Markers are notes with no status. Adding open/resolved status, plus a “carry open notes into the new version” step when you import a bounce, would turn the inspector into a revision checklist (“3 open notes from v4”).

    This needs a Supabase migration and iOS support (resolving notes on the phone fits the iPhone app’s purpose well), but it changes the app from an annotator into a revision tracker.

    Web + Electron + iOSSupabase migration
  5. 5

    Offline listening on iPhone

    Checking mixes in the car or on earbuds is the main reason to have a phone companion. The iOS README and plan doc already list encrypted persistent downloads and queued annotation writes as the next planned work.

    Without them, the app fails in exactly the places people do those listening checks.

    iOSAlready on the roadmap

Runners-up

  1. 6

    Secret-link sharing

    Let artists or clients listen and leave timestamped comments through a private link. The schema already reserves share_token_hash on songs.

    It could bring in the most new users, but it’s also the biggest job and the most security-sensitive, since it needs a public read path alongside the current row-level security.

    Web + serverSupabase policiesHigh effort
  2. 7

    Electron watch folder

    Watch the export folder of your audio editing software and automatically import new bounces into the matching song.

    It removes the most repetitive step in desktop use: exporting a mix, then dragging it into the app by hand.

    ElectronMedium effort

The first three share the song page’s playback code and would work well as one piece of work.
